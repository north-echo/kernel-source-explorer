## Inventory and approach

Reviewed all 64 opening questions/explanations, 128 optional concept sections with their assumptions/counterexamples, vocabulary, code illustrations, diagrams, reflection prompts, references, linked activities and containment worksheets. The initial inventory found: a prediction gate before essential definitions; process/memory/permission categories introduced as if already understood; copied lab containment inventories implying chapter-level observation; anonymous conceptual arrows; fragments without local syntax introductions; and generic discovery synonyms across unrelated topics.

Each revised guide has an individually authored situation and prerequisite reminder, a connected visible explanation, and a reflection after that explanation with an optional answer. The prose was written chapter by chapter; shared presentation/serialization does not supply generic filler introductions. Main ideas explain what a particular variable, process, record, descriptor or operation does before naming the mechanism. The vocabulary review checked every chapter term against its main explanation. Thirty-four shared glossary definitions were rewritten where the older wording was compressed, circular or overbroad; the remaining useful definitions were retained as reinforcement. Optional concepts retain exact interfaces, assumptions, contrasting cases and manual links. The book's chapter identities/order, printed-page ranges, titles, references and stable routes were preserved, and all 64 were compared with the baseline metadata.

The new ChapterReading presentation applies to chapter records with `orientation`. Older records and the nine developed investigations retain the previous compatible presentation. Reflection reveal uses existing per-topic display state, not a completion record. Saved notes/storage schema, book position and saved lab segments are unchanged. Legacy `view=containment` links remain valid through `security_connection`; their prose starts from the concrete attempted operation rather than technical worksheet fields. Related investigations are explicitly separate activities. Six potentially misleading comparison links now explain what the linked lab does and does not implement (credentials, resource limits, capabilities, IPC, descriptor transfer and networking acknowledgments). Reading availability remains separate from runnable experiments and reviewed source.

Diagrams now state the question they answer and the meaning of arrows, with a labeled accessible text equivalent. Existing corrected ownership/ACL/signal/private-versus-shared/condition-loop/acknowledgment models remain. The Chapter 2 model no longer suggests a fabricated libc-to-kernel trace; Chapter 38 narrows the intended helper job before action; Chapter 46 includes full capacity; Chapter 54 separates creator setup from peer discovery. Simple conceptual nodes remain static; optional annotated nodes still expose their explanation.

Every remaining code illustration identifies its kind, missing context and relevant C syntax before the code. Chapter 3 defers its premature thread-creation fragment; Chapter 59 now uses explicit pseudocode rather than a fragment that did not actually retain the connected descriptor. Complete reading illustrations remain labeled illustrations, not newly executed labs. No experiment or kernel mapping was added.

## Representative before/after decisions

- **Chapter 2:** “a running context with memory, credentials and references” assumed the categories it needed to explain. The replacement starts with a stored executable becoming a process, working memory holding an integer, and then the separate permission question. The inherited “Establishes independence” worksheet claim is removed; Lab 001 is explicitly a preview/separate activity.
- **Chapter 17:** the mask is introduced through a named entry that appears to allow a write but is limited to reading. Optional depth retains precise class/mask and default-ACL rules instead of requiring the reader to decode ACL terminology first.
- **Chapter 20:** generation, delivery, blocking, pending state and disposition are explained in order through a postponed notification. The ignored/blocked distinction remains carefully scoped; no complete signal counter is implied.
- **Chapter 30:** a consumer wants an item; a lock lets participants inspect/change the same queue coherently; its true/false test is then named a predicate. The recheck loop and the omitted error handling of the fragment remain visible qualifications.
- **Chapter 49:** selecting backing and selecting sharing answer separate questions. MAP_PRIVATE/MAP_SHARED are introduced after those choices, with synchronization, persistence and truncation kept distinct.
- **Chapter 61:** a client wants confirmation of an update. Local byte acceptance, remote processing and a meaningful application acknowledgment are explained as separate stages, with no guarantee that a reply arrives.

## Prerequisite ordering and evidence review

The early sequence establishes process/private memory, result conventions, descriptors and buffers before credential changes, ACLs and inheritance. Signals introduce a thread as one execution path when per-thread masks first matter; later thread chapters revisit that model and add lifetime/synchronization. IPC first separates framing, capacity and shared storage, then the individual mechanisms. Networking separates endpoints, addressing, framing and application meaning before server/event-loop details. Later guides include brief reminders for direct entry; they do not repeat an entire earlier chapter.
